# DDR-004: Replace the unimplemented backend plan with a curated static directory

## Context

The professor clarified that deployment does not require a server, but the
architecture must support the product's core job and match the implementation.
The checked-in Worker uses an in-memory map, has no D1 binding, and is not
deployed. Browser localStorage cannot share employee opt-ins with interns.

## Decision

Use a static JSON directory for intern search. Keep sample profiles fictional.
The opt-in form creates a local request file and JSON preview only; a maintainer
must receive it through an approved private channel, review it, update the JSON
file, and redeploy. An opt-out request also requires a private maintainer
handoff and republishing. Add a GitHub Pages workflow that publishes only the
app and its directory data.

## Consequences

The static site can be deployed without an application server and supports
search across names, teams, and topics. Opt-in and opt-out are not immediate,
and the sample directory does not test real employee matching. Published data
is public, so real employee details require explicit consent, organizational
approval, and privacy review. The site remains undeployed until Pages is enabled
and the workflow succeeds.
